# 第 9 章 定时任务与 IM 频道

重复的工作不应该靠记性。千问办公提供两套定时任务机制，加上 IM 频道推送，可以让结果在固定时间出现在你和团队面前。

## 两套定时任务：云端与本地

千问办公的定时任务分为两类，创建前必须先确认所在端：

| 项目 | Web 定时任务 | 桌面定时任务 |
|-|-|-|
| 运行位置 | 云端执行 | 本地客户端调度 |
| 运行前提 | 账号有效、任务配置完整 | 本机客户端运行、设备可唤醒 |
| 可用工具 | 以网页端能力为准 | 可用本地文件、浏览器等客户端能力 |
| 故障处理 | 平台侧重试与记录 | 需关注设备休眠、关机导致的漏跑 |

一句话选择：**只依赖在线信息的任务放云端；要碰本地文件、浏览器登录态的任务放桌面端。**

## 创建定时任务的五要素

```text
1. 频率：每天 / 每周几 / 每月几号，几点执行
2. 输入：每次执行读取什么（固定文件、网页、上次结果）
3. 动作：生成什么产物（报告、表格、网页更新）
4. 推送：结果发到哪（IM 频道、网盘目录、邮件草稿）
5. 失败策略：失败时重试还是通知人工
```

## 实战：每天早上 8:30 的行业简报

```text
创建一个定时任务：
- 频率：工作日每天 08:30
- 动作：搜索最近 24 小时关于【你所在的行业】的重要新闻和政策，
  筛选出与【你的业务关键词】相关的 5-8 条，
  每条给出标题、一句话摘要、来源链接和影响判断（利好/利空/中性）。
- 输出：生成 Markdown 简报，同时更新到指定网页。
- 推送：完成后发到我的 IM 频道。
- 失败处理：如果搜索失败或当天无相关内容，发送一条"今日无重要更新"，
  不要编造内容。
```

第 16 章会把这个例子完整跑一遍，并加上质量控制。

## 定时任务的管理习惯

- **看执行记录**：每次执行都应有记录；连续失败的任务要么修要么停，不要让它静默挂掉。
- **结果抽检**：每周抽查一次自动产物，防止模型或数据源变化导致质量漂移。
- **补跑机制**：桌面任务因设备关机漏跑时，确认是否支持补跑；重要任务宁可晚到，不可缺席。
- **数量控制**：定时任务越多，维护成本越高。只保留真正重复、稳定、有价值的项目。

## IM 频道：结果送到你面前

IM 频道把桌面端接入钉钉、飞书、微信、Slack 等消息平台。配置思路：

1. 在 IM 频道页选择平台，按引导完成绑定。
2. 选择接收结果的会话或频道。
3. 在定时任务或长任务里选择"完成后推送"。

团队使用时的建议：**给自动推送单独建一个群或频道**，避免机器人消息淹没人与人的沟通；推送格式固定为"结论 + 链接 + 异常提示"，方便扫一眼就做决定。
