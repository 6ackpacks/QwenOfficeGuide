# 第 4 章 快速完成第一个可验收的任务

这一章的目标只有一个：用 30 分钟完成一个真实、可检查、能复用的任务。

很多"AI 做得不好"的任务，根源不是模型不会写，而是人没有把交付标准说清楚。所以在动手之前，先把任务拆成五个问题。

## 任务五问法

| 问题 | 要说清什么 | 示例 |
|-|-|-|
| 目标 | 这份成果要帮助谁做什么决定 | 给部门负责人看，用于判断活动是否值得投入 |
| 受众 | 阅读者是谁，懂不懂背景 | 管理层只看结论；执行组需要过程和分工 |
| 材料 | 哪些文件是事实来源，哪些只是参考 | `销售明细.xlsx` 是唯一数据口径，去年方案只参考结构 |
| 格式 | 要 Word、Excel、PPT、网页还是多者联动 | 一份 8 页汇报 PPT + 一页数据附表 |
| 验收 | 怎么判断结果可用 | 数字能回到源文件，PPT 投屏不溢出，结论有出处 |

把这五个问题的答案直接写进提示词，任务质量会有肉眼可见的变化。

## 实战：把一份杂乱的数据变成周会材料

假设你手上有一份本周销售流水表（真实工作里随便一份都行），目标是周会汇报。

### 第一步：准备材料

把 `销售明细.xlsx` 上传到新任务输入区，或先放进个人网盘再选择它。

### 第二步：写任务描述

```text
【目标】基于本周销售明细，生成一份给部门负责人看的周会汇报材料，
帮助他判断下周应该加大投入还是收缩的品类。
【材料】销售明细.xlsx 是唯一数据口径，包含日期、品类、销量、销售额、退货量。
【格式】
1. 输出一份 8 页以内的 PPTX，结构：本周概览、品类排名、异常波动、下周建议、附录数据表；
2. 同时输出一份 Excel，包含按品类汇总的透视表，公式可刷新。
【验收】
- 所有数字必须能从销售明细.xlsx 追溯；
- 异常波动的判断标准请先告诉我，我确认后再写进 PPT；
- 下周建议只基于数据，不要虚构外部原因。
```

### 第三步：过程中回应两次确认

千问办公在执行中可能会问你：异常波动的阈值定多少（例如环比 ±20%）？建议页是否需要配图表？

**认真回答这两次确认**。这是"人工关口"的价值：让 AI 在关键判断上等你拍板，而不是自作主张。

### 第四步：验收

拿到产物后按顺序检查：

1. 抽查 3 个数字，回到 `销售明细.xlsx` 核对。
2. 打开 PPT 投屏预览，看文字是否溢出、图表是否清晰。
3. 刷新 Excel 透视表，确认公式没有断。
4. 检查"下周建议"有没有编造数据之外的原因。

### 第五步：不满意就说差异，不要重来

```text
在上一版周会 PPT 基础上修改，不要重新生成：
1. 第 2 页品类排名改为横向条形图；
2. 异常波动页补充每个异常品类的 top3 原因假设，并标注"待确认"；
3. 删除附录中重复的表格；
4. 输出 v2 版 PPTX，并在回复中列出本次改动清单。
```

**二次修改说差异，是千问办公最重要的使用习惯之一**。从头重做既浪费积分，又会丢失上一版已经正确的部分。

## 这个任务教会你的五件事

1. 任务五问法比提示词技巧更重要。
2. 上传事实材料，比口头描述可靠得多。
3. 过程中的确认提问，是质量的关键控制点。
4. 验收要动手抽查，不能只看"像不像那么回事"。
5. 返工说差异，不要推倒重来。

把这五件事记住，第二篇的所有案例都只是它们的变体。下一章讲模型和积分——同样的任务，怎么花得更值。
