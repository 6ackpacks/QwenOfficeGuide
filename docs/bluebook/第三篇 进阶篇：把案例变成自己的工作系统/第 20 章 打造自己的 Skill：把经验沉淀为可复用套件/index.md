# 第 20 章 打造自己的 Skill：把经验沉淀为可复用套件

你手里那些反复使用、屡试不爽的提示词，就是 Skill 的原料。这一章讲如何把个人经验变成可安装、可分享、可治理的专家套件。

## 什么样的经验值得做成 Skill

满足三个条件再动手：

1. **重复发生**：同类任务每月至少出现 3 次。
2. **方法稳定**：你已经连续成功 3 次以上，流程基本固定。
3. **标准明确**：说得清什么叫"做对了"。

反例：一次性的创意任务、每次输入差异极大的任务、你自己也没把握的流程——这些不适合 Skill 化。

## Skill 的结构

一个完整的技能/套件通常包含：

| 组成 | 作用 | 例子 |
|-|-|-|
| 知识 | 领域背景、判断标准 | 公司的报销制度要点 |
| 方法 | 执行步骤和顺序 | 先体检数据，再分析，再成图 |
| 模板 | 输入输出的固定格式 | 周报结构、证据表表头 |
| 关口 | 必须人工确认的步骤 | 发送前确认、金额复核 |
| 边界 | 不做什么 | 不给法律结论、不外发文件 |

## 两种创建方式

### 方式一：自然语言创建

在专家套件页选择"通过 QwenWork 创建"，直接描述：

```text
我想创建一个"客户拜访纪要"专家套件：
【岗位】B2B 销售
【任务】把拜访录音转写整理成标准纪要
【输入】录音转写文本、客户背景卡
【流程】1 提取事实（客户原话、需求、异议）→ 2 生成纪要 →
3 提取待办 → 4 等我确认后写入客户档案草稿
【输出标准】纪要模板见附件；待办必须有负责人和时间
【人工关口】写入客户档案前必须我确认
【边界】不承诺价格，不替客户做决定
```

### 方式二：定制已有套件

对已安装的套件选择"定制此套件"，在现有配置上叠加你的规则。适合行业通用套件 + 公司特殊规则的组合。

## 技术清单：plugin.json

套件包导出为 `.zip`，清单结构要求至少包含 `.qwen-plugin/plugin.json` 或 `.claude-plugin/plugin.json`，且 `plugin.json` 必须包含 `name` 字段。最小示例：

```json
{
  "name": "visit-notes-kit",
  "version": "1.0.0",
  "description": "客户拜访纪要标准化套件",
  "skills": ["skills/visit-notes.md"]
}
```

上传或安装他人套件前，解压检查清单、脚本、技能内容、外部连接和默认操作——**不能只根据文件名信任套件**。

## 团队分发 checklist

- 适用范围、输入、数据连接、执行顺序、输出标准是否写清。
- 人工关口和失败处理是否明确。
- 版本负责人是谁，更新和回退流程是什么。
- 正常样本、错误样本、权限不足样本是否都测试过。

## 避坑清单

- 先用真实任务验证方法，再做套件；顺序反了就是"把错误标准化"。
- 更新套件会覆盖个人修改，更新前导出现有版本。
- 一个套件只解决一类问题，大而全的套件没人敢用。
- 涉及专业判断（法务、财税、医疗）的套件，必须保留专业人工关口。
