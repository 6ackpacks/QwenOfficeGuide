# 第 22 章 自动化的可靠性：验收、日志与回退

自动化任务的价值 = 稳定性 × 信任度。一次离谱的错误，足以让团队再也不用一个本来很好用的自动流程。这一章给出可靠性的四个支柱：验收标准、执行日志、异常处理和回退机制。

## 支柱一：验收标准写在前面

每个自动化任务上线前，回答四个问题：

| 问题 | 示例 |
|-|-|
| 输出格式对不对 | 早报必须是固定四段结构 |
| 内容从哪里来 | 数字只来自 sales-daily.xlsx |
| 什么情况下必须停 | 数据源缺失、格式变化时停止并报警 |
| 谁对结果负责 | 值班同事每天抽检一次 |

把这四个答案直接写进任务描述，而不是留在脑子里。

## 支柱二：执行日志

可靠的自动任务要留下三类痕迹：

1. **执行记录**：何时开始、何时结束、成功还是失败。
2. **输入快照**：这次执行读取的是哪个版本的材料。
3. **产物版本**：输出物带日期或版本号，可追溯。

提示词里可以明确要求：

```text
每次执行完成后，在产物末尾附加执行信息块：
执行时间、数据源文件及修改时间、本次使用的关键参数、
是否有异常或降级处理。
```

## 支柱三：异常处理

异常不可避免，沉默最可怕。分级处理：

| 异常类型 | 策略 |
|-|-|
| 数据源缺失 | 产物中标注缺失，其余照常；连续两次缺失则通知人工 |
| 格式变化 | 停止处理，报告差异，绝不猜测新格式的含义 |
| 权限失效 | 通知人工重新授权，不用缓存硬撑 |
| 结果异常（如数字突变） | 照常输出但标注"波动异常，建议人工复核" |

核心纪律：**宁可报告失败，不可编造成功。**

## 支柱四：回退机制

- 产物版本化：v1、v2 或日期命名，新版出错可以退回旧版。
- 操作可逆：涉及修改外部系统的自动化（发消息、改文档、提交审批），先确认系统支持撤回，或改为"生成草稿 + 人工发送"。
- 配置备份：定时任务、套件的配置定期导出，误删可以恢复。

## 上线前的可靠性检查清单

- 连续手动跑通 3 次，结果一致。
- 故意制造一次异常（改个文件名、断一个数据源），看它怎么反应。
- 确认失败通知能真正送达（而不是静默失败）。
- 明确抽检责任人，写进任务文档。
- 运行一周后复盘一次，再决定是否扩大自动化范围。

## 一个心态

自动化的目标不是"不用人"，而是"人不用做重复的部分"。把重复劳动交给机器，把判断、确认和责任留给人——这是自动化长期存活的前提。
